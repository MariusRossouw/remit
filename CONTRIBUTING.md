# Contributing to Remit

Remit is at the vision stage. There is no code to patch yet, so the most valuable contributions are arguments.

## What helps most right now

- **Tell us where the idea breaks.** Open an issue describing an attack, a use case, or an adoption problem the documents do not handle.
- **Answer a design question.** The open questions are listed at the end of [the scenario](docs/scenario.md). Pick one and propose an answer in an issue.
- **Point out prior work.** If something in [positioning](docs/positioning.md) is wrong, out of date, or missing a project, say so with a link.

## Changes to the documents

Small fixes can go straight to a pull request. For anything that changes a principle, the contract syntax, or a milestone, open an issue first so the reasoning is recorded.

## Sign your commits off

Every commit must carry a sign-off line stating that you have the right to contribute it, under the [Developer Certificate of Origin](https://developercertificate.org/):

```
git commit -s -m "Describe the change"
```

This adds `Signed-off-by: Your Name <you@example.com>` to the commit message. There is no separate agreement to sign.
